# Phase 2 — Legal Named Entity Recognition (L-NER)

Task: predict character spans `[start, end, LABEL]` for 12 entity types (APP, RESP, A.COUNSEL, R.COUNSEL, JUDGE, WIT, AUTH, COURT, STAT, PREC, DATE, CASENO) in Indian court judgments. Metric: strict macro-F1 (exact start, end and label). Only our own Phase-1 models are used; each is wrapped as a backbone and given a token-classification head, then adapted to the 70 labelled judgments (two folds of 35) and evaluated on a hidden test fold on Codabench.

## Method in one paragraph
Judgments are tokenised with the Phase-1 A1 BPE tokenizer (character offsets recovered per token), tagged with 25 BIO tags, cut into overlapping windows (2048/1024 tokens by default) and passed through a Phase-1 backbone with the language-model output layer removed. A BiLSTM + linear head produces per-token tags; overlapping windows are merged, decoded with BIO-constrained Viterbi, and span edges are repaired with a punctuation trim table learned from the training fold. Backbones are adapted with full fine-tuning, partial fine-tuning, BitFit, LoRA, LoRMA (LoRMA+ and LoRMA_π), Houlsby/Pfeiffer adapters, or prefix tuning. A distilled LSTM student and a span-voting ensemble were also built. Full details: [`results/phase2-METHODS-detailed.md`](results/phase2-METHODS-detailed.md).

```
  code/                    # engine (p2_core.py), alignment (lner_align.py), backbone wrappers, notebook builders
    phase1_model_sources/  # Phase-1 model code embedded in the notebooks
  results/                 # master results, detailed methods, per-experiment write-ups, changelog

```
Notebooks are self-contained Kaggle notebooks (GPU T4; Run All). They are generated by the scripts in `code/build_p2_*.py`; the engine code in `code/` is embedded in each notebook, so no helper `.py` files are needed to run them.

## Running
1. Kaggle notebook, GPU T4, internet on, Kaggle secrets `HF` (read) and `HF_WRITE` (for the model bucket). Tokens are read from secrets only and never written into cells.
2. Attach the course dataset (fold text/gold files) as the notebook expects; data files are NOT in this repository (course data).
3. Run All. Sweep notebooks resume if the session stops (finished setups are cached in the bucket).
4. Ensemble notebooks need a Kaggle dataset of the submission zips (`prediction.json` per model).
The builder scripts have `/home/claude/p2/` paths hard-coded from the authoring environment; adjust `P` at the top of `build_p2_notebooks.py` if you regenerate notebooks.
